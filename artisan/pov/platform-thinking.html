Platform Thinking & System-Level Thinking

How I apply the two hardest skills for a product manager to replace with AI — by building a team-wide operating system that spans five product lines, gives every feature one single source of truth, and keeps 20 live dashboards in sync automatically, with no manual data entry.

Why This Matters
A product manager's time either goes into doing individual tasks — writing tickets, chasing status updates, rebuilding the same deck every quarter — or into designing a system that keeps itself organized. I built the second one, for a whole team, not just myself.

Where I Invest
Designing the System
Designing the shared structure, rules, and automation a whole team runs on
This kind of "big picture" thinking is about:
◆ Designing one shared way of organizing information that works across every product line, instead of a different one for each team
◆ Knowing what's actually possible when connecting different systems together — and what isn't
◆ Building safety checks and automation that keep working as more people use the system, not just for one person
◆ Treating the internal tooling itself like a real product — with its own roadmap, quality checks, and health checks
A Team Operating System, Not a Personal Tool
A simple text-file-based workspace, run through an AI coding assistant, that every product manager, designer, engineer, and reviewer on the team uses to find or add the latest information on a feature. It now covers five product lines and 100+ tracked features across six releases — this is the actual daily system the team ships with, not a side project.
One single source of truth per feature
One file lists every feature's owners, linked work items, and every other system it touches — replacing status meetings with a file everyone already has open.
Every feature's folder tells its own story from start to finish
Reference materials (designs, research, meeting notes, early findings) → the actual spec → what was shipped (release notes, scope cuts, screenshots) → handoff docs for other teams → what's next. Opening any feature's folder in order shows the full decision trail without asking anyone.
Releases are tracked as their own thing
One master list tracks every release's status (planned / in progress / shipped), and every feature is filed under its release rather than loosely under the product — so "what shipped when" is built into the file structure itself, not a separate spreadsheet.
Plain text as the one shared source
Easy for people to read, tracked for changes over time, and easy for AI tools to read too — dashboards and AI tools read the exact same file the team edits by hand, so nothing goes out of sync.
Dashboards that update themselves
Editing one file automatically updates every dashboard that depends on it — no separate admin tool, no "someone forgot to update the tracker."
One combined view, not four separate ones
One dashboard shows every feature across all five product lines, grouped by stage (scoping / active / shipped) and automatically flagged if it's at risk.
One consistent look across 20 pages
The same look and feel — dark mode, sorting, search, side navigation — across every page, kept simple and consistent by design.
Automatic Checks, Not Relying on Memory
Automatic checks run at key moments instead of relying on anyone remembering to do them. This is system-level automation that keeps things running correctly as more people use it — the full access-control system built on top of these checks is its own proof point. See Agent Governance →
Dashboards that update themselves
Editing a feature record, the team roster, or the tool list updates every dashboard that depends on it — no manual "refresh the site" step.
A tool catalog that stays current on its own
Adding a new reusable tool or AI agent automatically updates the catalog other teammates browse — it can never silently go out of date.
Checking who gets mentioned
Any document that mentions a teammate is checked against the current team list before it's saved — no more pinging someone who left the team or a mistyped name.
Usage data, captured automatically
Every use of a tool or AI agent across the team is logged and rolled into a usage dashboard — adoption data nobody has to manually compile.
A Team of Specialized AI Agents
Roughly 30 specialized AI agents, each focused on one job, working together rather than one generalist trying to do everything. A few examples:
A competitive-analysis agent that adapts per product
Figures out which product line a feature belongs to, then compares it against that product's specific competitors — a maintained list for the mature product, freshly researched for the newer ones.
StrategyCompetitive Intel
Quality and health-check agents
One agent thoroughly tests every dashboard before a leadership review; another checks the whole workspace across nine health areas — organization, up-to-date info, naming — and writes a prioritized fix list.
QualitySelf-Auditing
A coach for how the team uses AI tools
Reviews how the team is actually using the AI tools and returns specific, prioritized suggestions for improvement — the system watches its own adoption, not just whether it's running.
AdoptionCoaching
A chain of design reviewers
A completeness check, a design critic, and a final readiness check run one after another before any design goes to engineers — each one focused narrowly enough to stay reliable.
DesignHandoff Quality
A Library of Reusable Shortcuts
70+ self-contained shortcuts cover the product manager's job end to end — some adopted from a shared cross-team set, the rest built specifically here, and a few clearly marked as "not fully ready yet" until confirmed. Organized into clear groups rather than one long list:
Research
Customer insight, market, competitive, persona/JTBD, and tech-feasibility sweeps — each ending in a source-cited notes file, never a guess.
PRD Authoring
Problem definition, PRD drafting, structured critique, and a scored fidelity check before anything reaches engineering.
Planning & Records
Roadmaps, OKRs, opportunity scoring, and structured records for the team's internal work-tracking system.
Communications
Audience-aware status updates, meeting prep, and reply drafting — every send gated behind explicit approval.
Presentations
One orchestrator plus content-gathering skills per source type (release, feature, roadmap, ad hoc) feeding a single branded deck builder.
Design & Prototyping
Wireframing, prototyping, and design-to-engineering handoff, gated by a shared design-system context layer every other design skill loads first.
Layered Context Files
26 context files, organized from broad to specific, like organizing a company into teams and sub-teams. Each file limits what the AI knows and does at the right level — the same way a team charter or clear job boundary would for a person.

Connecting Systems Together
10+ different tools reachable from one place — not separate tools bolted together after the fact. A single working session can search shared email and chat, pull real usage and market data, generate a branded presentation, and update the team's records — all without re-entering the same information twice.
Email, calendar, and chat search
Grounds status updates, meeting prep, and reply drafts in the actual thread — not a paraphrase from memory.
Usage, market, and account-health data
Quantified adoption and market signal feeds directly into research notes and account-level briefings instead of anecdote.
The internal work-tracking system
Feature records, delivery status, and risk roll up from the same system of record the rest of the org already uses — no shadow spreadsheet.
Presentation generation and document conversion
Decks and one-pagers render from the same structured content bundle the research and PRD skills already produced.
