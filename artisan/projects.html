PM Operating System
A markdown-based operating system for one Product Manager — task tracker, 1:1 sync hub, backlog, and strategic playbook, all served from a terminal with zero installs.

Runs entirely on markdown files served as live dashboards — task management, weekly 1:1 tracking, product backlog, and a strategic-playbook visualizer, all updating in real time over SSE with no build step and no external services.
Why It's Built This Way
  • Zero npm dependencies — smaller attack surface, no supply-chain risk, proves out production infra with fundamentals only
  • Markdown as the data layer — human-readable, version-controlled, and directly parseable by an AI agent
  • Live updates via SSE — dashboards refresh the instant a markdown file changes, no polling
  • 24 CLAUDE.md governance files — a hierarchical instruction system that scopes how AI behaves per directory, like a team charter for agents

Team Operating System
The team-scale extension of the PM Operating System — one shared, version-controlled workspace where PM, design, engineering, and research converge on the same feature instead of five disconnected tools.

Generalized as an open-source skeleton, not tied to any one company's internal system. Every feature — regardless of who's building it — gets the same folder shape, so a PM's spec, a designer's file, and a researcher's notes live next to each other instead of three tools apart.
Why It's Built This Way
  • One canonical record per feature — meta.yml maps owners, tracker links, and dates; nothing else duplicates it
  • Structured consistency — every feature looks the same, so anyone (including an AI agent) can navigate any feature without being told where things are
  • Roles converge, not diverge — one shared workspace instead of five disconnected tools
  • Plain text, version-controlled — markdown and YAML, diffable in a PR like code, no vendor lock-in
Feature Folder — the Core Pattern
features/<release>/<feature-name>/ ├── meta.yml # owners, tracker, dates, status ├── 01-references/ # designs, research, feasibility ├── 02-spec/ # PRD, prototypes, open questions ├── 03-shipped/ # release notes, tech spec, screenshots ├── 04-handoff/ # cross-team rollout transfer └── v2-backlog.md # deferred scope, what's next
